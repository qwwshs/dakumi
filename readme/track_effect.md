# 每条轨道的效果（开发中）

`chart.json` 中的 `effect` 是列表。每条效果必须填写 `track`，只影响该编号的轨道，不支持旧的全局效果格式。

```json
{
  "track": 1,
  "type": "note_alpha",
  "beat": [4, 0, 1],
  "beat2": [8, 0, 1],
  "from": 100,
  "to": 0,
  "trans": {"type": "easings", "easings": 1}
}
```

这个例子让轨道 1 的音符在第 4 到第 8 拍之间逐渐变透明，其他轨道不受影响。

- `track`：轨道编号，必填。
- `type`：`note_alpha` 是音符透明度，`track_alpha` 是轨道底板透明度，`track_line_alpha` 是轨道侧线透明度，`note_rotate` 是音符旋转角度。透明度默认 100，旋转默认 0。
- `beat` / `beat2`：起始和结束节拍，写法与 event 一样。
- `from` / `to`：起始和结束数值。
- `trans`：与 event 共用缓动和贝塞尔计算。
- `time_offset`：可选的正数毫秒偏移，作用于该效果自身的起止时间。

开始之前保持默认值；结束之后保持 `to`。同一轨道同一种效果有多条时，采用已经开始且起始时间最近的一条；起始时间相同则列表中后写的优先。拖回之前的时间会重新计算，不保留未来的结果。

开发接口：`effectService:calculate(trackIds, currentBeat)` 返回按轨道编号分开的效果表；`play:get_effect(trackId)` 返回对应轨道当前帧的结果。

## 下落速度与位置跳变

- `scroll`：当前下落速度，默认 `1`。`2` 是两倍速度，`0` 是停住，负数是反向。与其他效果一样，`from` 到 `to` 在 `beat` 到 `beat2` 之间过渡；之后保持 `to`，直到下一条 scroll 开始。计算位移时会对速度积分，不会简单地把整条音符位置乘上当前速度。
- `jump`：当前时间偏移，默认 `0`，单位为拍；不是毫秒；默认的“当前值”模式不累加以前的 jump。实际读取的时间是“当前拍数 + 当前 jump 值”。同样支持 `from` / `to` 和缓动。

这里沿用 demo 原有的拍数坐标：令 `F(t)` 为 scroll 速度的积分，`J(t)` 为当前 jump，当前时刻为 `now`，音符判定时刻为 `hit`，到判定线的距离为：

```text
距离 = F(hit) - F(now + J(now))
```

只在当前时间到达 jump 的起点后读取它，不提前读取音符时刻的未来 jump。例如 25 拍处有 jump=3，20 拍仍读作 20，25 拍才读作 28；此时原本位于 28 拍的音符显示在判定线上。有效显示时间等于音符时刻时，距离为零。scroll 和 jump 只改变 demo 的显示轨迹，不改变音符判定时间，也不改变 edit 区的时间网格。hold 的头和尾分别计算。

例如设置一条 `track: 1`、`type: scroll`、`beat: [4,0,1]`、`beat2: [4,0,1]`、`from: 2`、`to: 2`，轨道 1 从第 4 拍开始使用两倍速度，持续到下一条 scroll。

实现采用分段自适应积分，在效果起止及下一条效果的起点处分段；播放时通过二分查找取值，音符位置的积分跨帧复用；各轨道共用积分结果，并在谱面变化后重建缓存，前后拖动时间都会重新取值，不使用帧间累积。

## 在编辑器里编辑

在顶部工具栏的“效果编辑”区域点击“编辑效果”，右侧编辑区切换为五列：

```text
scroll | jump | track_alpha | track_line_alpha | rotate
```

操作与普通 event 相同：使用原来的放置事件快捷键先放起点、再放终点；点击效果可在原来的事件属性页调整起始值、结束值、缓动和偏移时值。删除、框选、复制粘贴和撤销重做继续使用原来的操作。轨道编号决定效果作用于哪条轨道，多标签页也使用上述五列。

`rotate` 是旋转效果，单位与现有音符旋转相同。点击“退出编辑”恢复 note / x / w / lpos / rpos 五列。切换时会取消尚未完成的放置与框选，效果数据单独保存在 `effect`，不会写进 `event` 或修改音符。

## Jump 的两种计算方式

侧栏“偏好”中的“Jump 计算方式”可选择：

- **当前值**（默认）：采用最近一条已经开始的 jump，支持起始值、结束值和缓动，不累加。
- **累计（只使用终值）**：到达每条 jump 的起点时立即加上它的 `to`；`from`、终止时间和缓动不参与计算。只累计当前轨道中已经到达起点的 jump，向前拖动可直接计算，向后拖动会去掉尚未触发的项。

例如 25 拍有 `to=3`，30 拍有 `to=2`：累计模式在 25 拍读作 28，在 30 拍读作 35。

点击“保存”后写入该谱面的 `preference.jump_mode`，字段值为 `current` 或 `cumulative`，支持撤销和重做。


## Malody 导入谱的位移

Malody 插件设置 `preference.motion_mode = "malody"`。该模式的 jump 单位为**毫秒**，保留原谱数值，累计模式仍只使用 `to`。scroll 在音频秒轴上积分；以首个 BPM 换算为显示距离。音符和当前播放位置共用累计位移。每条 jump 先乘以它触发时的 scroll，再进行累计；之后改变 scroll 不会重新缩放已经发生的 jump：

```text
P(t) = scroll 在 0 到 t 秒之间的积分 + Σ(已触发的 jump 毫秒值 × 各自触发时的 scroll) / 1000
距离 = (P(音符时间) - P(当前时间)) × 首个 BPM / 60
```

这样在巨大累计 jump 之后，即将到达的音符仍能显示，音符到达自身时刻的距离仍为零。后退播放位置会重新查找，不残留未来的效果。未设置 `motion_mode` 的 Dakumi 谱面继续采用上面的拍数与当前读取时间算法。


效果仅在进入 demo 模式后参与渲染，编辑时的 demo 预览使用默认速度、透明度和旋转。音符按真实判定时间移除；判定前只要位于整个 demo 区域内就会绘制，包括判定线下方。长条在尾部判定后移除。
