# 自动检查与备份保留

## 本地检查

需要 Python 3 和 LuaJIT（Lua 5.1）。Windows 默认寻找 LÖVE 安装目录中的 `lua51.dll`，也可用 `--lua-library` 指定；有独立 LuaJIT 命令时可用 `--lua`。

```powershell
python scripts/run_tests.py --syntax
python scripts/check_boundaries.py
python scripts/run_tests.py
python scripts/run_tests.py --integration --love 'C:/Program Files/LOVE/love.exe'
python scripts/run_tests.py --ui --love 'C:/Program Files/LOVE/love.exe'
```

纯 Lua 回归自动发现 `tests/*.lua`，每个测试使用独立进程。`--syntax` 只编译 Git 中的 Lua 文件和未忽略的新文件，不执行应用。静态边界检查约束插件使用 `ctx.ui`、模型不得引用服务与业务对象、基础 note/event/track 工具不得反向引用服务。

`--integration` 运行 safeInput、谱面变更、音频服务、BPM、声纹图、改键与轨道筛选的真实 LÖVE 测试；`--ui` 运行完整编辑输入测试。UI 集成测试还需要本机可用的 Nuklear 原生库。测试使用虚拟谱面或临时音频，不允许读写真实用户谱面。声纹图报告和截图保存在忽略的 `.zcode/` 中。

GitHub Actions 在 push、pull request 和手动触发时执行语法检查、架构边界检查、Luacheck 和全部纯 Lua 回归，并在 Xvfb 中运行 LÖVE 11.4 集成测试。Luacheck 当前严格检查自动备份、声纹配置、改键捕获与音符皮肤模块；其余历史模块仍由语法、边界和回归检查覆盖。另一 Windows 任务运行仓库自带 Nuklear 的完整编辑输入回归。

## 自动保存保留策略

自动保存开关和周期维持原有设置。备份写入成功后，`src/utils/autoSaveRetention.lua` 规划并清理 `users/auto_save/` 中较旧的自动备份。

| 设置字段 | 默认值 | 中文说明 |
|---|---|---|
| `auto_save_keep` | 50 | 每张谱面最多保留 50 份 |
| `auto_save_days` | 30 | 清理超过 30 天的较旧备份 |
| `auto_save_max_mb` | 256 | 自动备份总容量目标，单位 MB |

字段未填写时使用默认值。可在关闭程序后修改 `users/settings.json` 中的同名字段；异常值会回退或限制到安全范围。每张谱面始终保留最近一份，因此很多谱面或单份体积很大时，总容量可能高于目标。

新文件名包含谱面路径的 SHA-256、保存时间与序号，避免同名谱面混淆、名称中的斜杠和同秒覆盖。旧的“年 月 日 时 分 秒歌曲名-谱面名.json”也参与保留策略；旧格式只能按歌曲名与谱面名区分，并单独保留最后一份。

清理仅处理符合备份命名的普通文件，不递归进入子目录，不删除其他文件。新备份写入失败时不进行清理；旧备份删除失败只记录日志，不把已经成功写入的新备份报告为失败。测试全部使用虚拟目录；开发验证不会直接清理现有用户备份。
