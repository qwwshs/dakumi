# 元件的偏移时值

音符、wipe、hold、普通事件和放置在谱面上的事件组实例，都支持“偏移时值（ms）”。选中元件后，在侧边栏填写。

填写正数会让整个元件晚发生相应的毫秒数。例如 25 表示晚 25 毫秒，0.5 表示晚 0.5 毫秒。hold 和事件的起点、终点一起移动，原来的秒数长度保持不变。

留空表示不偏移。0、负数、无穷大和非数字输入不会应用，侧栏会给出提示。旧谱面没有该字段时，原来的位置保持不变。

偏移先按谱面的 BPM 表换算成时间，再加上毫秒值，因此经过 BPM 突变或渐变时也不会把毫秒误当成固定拍数。

## 保存与编辑

谱面使用英文可选字段 `time_offset`，单位为毫秒，只保存有限正数。没有偏移时省略该字段。例如：

```json
{
  "type": "hold",
  "track": 1,
  "beat": [4, 0, 1],
  "beat2": [8, 0, 1],
  "time_offset": 25
}
```

`beat` 和 `beat2` 仍保存基础节拍。若 BPM 为 120，上例的起点为 2.025 秒，终点为 4.025 秒。偏移也用于编辑区显示、试听、命中提示、框选、删除、历史范围及 Takana 导出的实际时间。

复制、粘贴和事件切割会保留偏移值；粘贴按基础节拍整体平移，预览与最终放置位置一致。拖动起止点时，会反向扣除偏移再保存基础节拍，避免重复叠加偏移。修改可以撤销、重做。

## 事件组

事件组实例的偏移会移动整个实例的起止时间，也会移动它占用的轨道时间范围。在偏移后的范围内，仍不能放置其他事件或事件组；侧栏输入若产生重叠，会保留原值并提示。

事件组内部的普通事件也支持各自的 `time_offset`。组内编辑时可在事件侧栏修改。组内实际起止点先考虑偏移，再按最早起点和最晚终点归一化，映射到放置实例的时间范围。事件组定义本身是一组可复用的数据；它在谱面上的位置由实例控制。

## 开发接口

- `getTimeOffset()` 返回毫秒数，未设置返回 0。
- `setTimeOffset(value)` 仅接受有限正数；传入 `nil` 取消偏移，0 和非法值会报错且不会改动数据。
- `getBeat()/getBeat2()` 返回保存的基础节拍表。
- `getBeatValue()/getBeat2Value()` 返回考虑偏移后的实际节拍数值。
- 复制、相等比较、JSON 序列化和 setter 撤销记录均包含此字段。

基础工具 `src/utils/timeOffset.lua` 由 ChartService 注入谱面时钟，模型不反向引用服务。变更偏移或 BPM 后，服务按实际时间重新排序，并维持侧栏选中对象。导入的非法偏移值会被忽略；外部代码写入时应通过 setter 校验。
